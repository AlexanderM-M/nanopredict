# Prospective evaluation protocol version 2 — yield-focused scope

Models, endpoint, checkpoint windows, comparator settings, blinding and analysis rules are unchanged. No study enrolment is recorded in the transferred snapshot. Freeze this revision only in a new study directory; existing version-1 studies retain their original protocol and evaluator.

Status: operational protocol for an initial prospective feasibility study, pending investigator sign-off and sequencing-machine qualification. No independent evaluation outcomes have been inspected or used to choose these settings. The historical replay subset and previously analysed retrospective datasets are development evidence. A file/header-only intake of newly supplied runs does not by itself assign their scientific role; eligibility and independence remain to be established. The old cluster's analysis directory is unavailable and is not a prerequisite requested from the operator.

## Population and grouping

Enroll consecutive routine MinION acquisitions after the study freeze, with live basecalling enabled and before the first intended checkpoint. Record every discovered or screened run, including exclusions and failed enrolment. The collector retains a count of detected but unregistered acquisitions; the site screening log must additionally capture acquisitions that start and end during a recorder outage. PromethION, calibration acquisitions, no-live-basecalling runs and known development-related cases are excluded with a predefined reason. An application start after a checkpoint never authorizes reconstructing that checkpoint for the primary analysis. Later, timely checkpoints remain eligible if the run was enrolled beforehand.

Use one opaque group UUID for the connected component of related patients, specimens, libraries, reused flow cells and restart acquisitions. Keep the identity-to-code crosswalk with the authorized site custodian, outside Nanopredict exports. Never derive these codes by hashing a patient name or medical-record number. The independent recruitment review must confirm that patients/materials are new relative to development and that known related runs stay together. When this cannot be established, do not assert independent eligibility. Future acquisition time prevents the same acquisition entering training but does not establish patient-level independence. Original bundled-model patient membership remains unresolved; if new recruitment cannot resolve independence adequately, an auditable newly developed model and new untouched cohort are required.

## Endpoints and stopping

Primary candidate endpoint: total final passed bases after acquisition ends and basecalling has drained, using the frozen pass filter and a reconciled final report/counter. Predictions target observed-ending yield under routine decisions. They do not estimate counterfactual yield had an intentionally stopped run continued. Maintain the original planned duration, later plan/filter/basecaller changes and final duration in the controlled run registry.

Record planned completion, intentional stop, interruption, failure or unknown explicitly. These categories are retained in the primary endpoint, with descriptive stratum-specific results; never select only scheduled successes. Runs ending before a checkpoint are absent from that checkpoint's risk set but remain in the cohort flow. A missing final outcome stays missing, not zero. Zero is used only for a verified zero yield. Treat a restart as a new acquisition with the same related-group UUID and a site-side restart link. An interrupted run has its own recorded endpoint; do not silently sum restarted acquisitions. Final counts must correspond to that acquisition only.

A fixed-duration yield endpoint is not evaluated by this protocol. It would require a separately frozen duration and measurement scheme, plus explicit censoring/competing-event handling when sequencing stops early.

## Freeze before enrolment

The study `init` command copies and hashes the three existing 30/60/120-minute artifacts, their fitted preprocessing and historical calibration. It does not fit or choose bundled estimators or recalibrate their intervals. It records software package versions, all package Python source hashes, the frozen evaluation-script hash, a copy/hash of this protocol, targets and baseline settings. Changes to frozen files or the installed package halt collection; a new phase requires a new directory and documented prospective amendment. Stored original calibration remains a historical method, not proof of prospective coverage.

Comparator set: cumulative-rate extrapolation to planned end, recent-rate extrapolation to planned end, development-set median and mean. The replay labels are deterministically split with seed 20261008: the first ceil(25%) of permuted labels form a baseline-calibration set; remaining labels define the mean/median. Each horizon is handled separately. These data are explicitly development, not independent validation. Baseline residual intervals use the held development-calibration residuals on the log1p scale, finite-sample quantile correction, and unbounded intervals when calibration counts are insufficient. Empirical residual target probabilities use fixed Laplace smoothing. No original bundled predictions are evaluated on replay to derive these baselines.

Freeze targets at 1, 5 and 10 Gb by default, or specify them at study initialization before any new outcomes. Freeze the 30/60/120-minute checkpoints, 20-second polling, maximum 120-second collection/computation delay, and maximum 120-second age of the yield snapshot. The study records actual receipt and prediction-ready times. A late, stale, unavailable or failed checkpoint is retained as a missingness/status event and is not backfilled. API subfeature availability before receipt is unknown; input timing equivalence remains a separate validation requirement. Receipt after the nominal horizon is allowed only within the declared operational window and is reported.

## Blinding and operational recording

Use the separate headless recorder. Do not start the prediction dashboard for enrolled runs; the recorder creates no browser or HTTP endpoint, displays no forecasts, and calls no run-control RPCs. Place the study directory under the data custodian's access controls. File permissions are a starting point; the same account can still read its own predictions, so process design and operator confirmation are required. Predictions must not influence stopping. At outcome entry, confirm whether blinding was preserved. Unconfirmed/violated blinding is reported and excluded from the primary blinded comparison, not hidden as a successful result.

The event log stores exception classes rather than raw RPC error text. Final outcome entry requires a reconciled source checksum, end time, end reason and final bases or missingness. Database uniqueness protects checkpoint/outcome records against overwrites. No automatic disconnection-to-stop-reason inference is made. Keep deviations/corrections in the controlled site log; do not edit stored predictions. SQLite persistence provides atomicity and restart protection, not an external timestamping service or tamper-proof audit trail.

## Analysis locked before outcomes

The primary comparative analysis uses the intersection of eligible, timely, blinded, outcome-observed runs with predictions from every frozen comparator at each horizon. All methods receive exactly that same set. This complete-case set may exclude many runs with missing recent rates or planned duration; report screening, pre-checkpoint endings, missing outcomes, misses, and comparator-unavailable counts alongside the metrics. Completeness is a primary feasibility result. Never describe common-case accuracy as accuracy for all enrolled runs.

Report MAE (primary point-error metric), RMSE, median absolute error, signed bias, and paired MAE differences versus cumulative extrapolation. For 80/90/95% prediction intervals report coverage, mean width and interval score; unbounded intervals count as vacuous coverage and must be shown. Report target-event counts, Brier scores and reliability diagnostics without asserting calibration from a small sample. Use 2,000 fixed-seed related-group bootstrap draws, jointly for compared methods, separately at each checkpoint, for 95% percentile intervals on error, coverage, width, interval score and paired differences. These quantify sampling uncertainty conditional on frozen predictors and known groups; do not pool checkpoints as independent runs. No bootstrap interval is reported for a one-group stratum, and infinite-width estimates retain their unbounded status. Because coverage bootstraps degenerate when every run is covered, also report the fraction of related groups whose runs are all covered at a horizon, with a 95% Wilson interval treating distinct groups as independent binary units. This joint group-coverage estimand differs from marginal run coverage and is labelled separately; it does not correct unknown relationships.

The evaluator reads recorded predictions only and has no fitting or model-selection step. Predeclare any later analysis amendment and label it exploratory. A 20–30-run consecutive pilot is a practical feasibility starting point, not a journal requirement, calibration proof or a confirmatory sample-size justification. Following the pilot, choose a separately recruited untouched confirmatory cohort and size it against a justified precision objective; any changes based on pilot outcomes make the pilot development evidence.

## Sign-off and evidence gates

Before initialization, the investigator and site custodian must record sign-off in the controlled study log for eligibility, grouping/independence, endpoint source, blinding, pass-filter consistency, clock synchronization and the protocol version. This is study governance, not an extra software permission request. Qualify the recorder on the actual machine with non-study material first. Do not label qualification runs as reserved independent cases. Hardware/Core compatibility, subfeature timing parity, source report reconciliation and real operational measurements remain unvalidated.
