## Material timing and interpretation risks

A late application start reconstructs all eligible checkpoints from the present API response. The recorded nominal horizon is therefore not necessarily when its prediction was available to an operator. Planned duration and basecaller settings may have changed; historical basecall counters may have been revised as backlog cleared. Record wall-clock collection and source availability times, and distinguish genuinely prospective checkpoints from backfilled ones. The benchmark's timing assertion is a review gate, not automated proof of causality.

`diagnose_run.metric_value` subtracts the zero target-temperature placeholder from measured temperature. Its resulting 'deviation' is approximately absolute temperature and must not be interpreted as distance from a real configured setpoint. Changing the model input now would create another distribution mismatch; collect the real setpoint in a separate study field and resolve both extraction and diagnostic reference before making a physiological temperature-QC claim.

BAM fallback observes completed files, whereas API progress can include earlier counters. Barcode yield data inherit BAM flush and polling delays. Run-level and barcode passed bases should be compared only at matching completion boundaries and with identical read filters. Neither BAM fallback nor a selected barcode receives the run-level bundled forecast.

## Required parity experiment

Freeze Core/API versions, basecaller model, Q filtering, chemistry and clock synchronization. For each run and 30/60/120-minute checkpoint, save an immutable feature vector at wall-clock collection plus sanitized source-response metadata, actual last observation time and missing-field reasons. Save final source reports separately. Re-extract the same checkpoints using a versioned historical extractor when available. Compare every feature with a declared unit, denominator, time window and absolute/relative tolerance. Report paired error distributions, missingness discordance and time-to-availability. Investigate discrepancies before retraining or claiming parity; do not silently rescale them to improve model performance.

Include delayed basecalling, changed planned end time, late app start, sparse boxplots, missing optional RPCs, pore scans just before/after a checkpoint and both replay resolutions. Empty or stale data should be identifiable, and no field available only after a checkpoint should be treated as contemporaneous. The current work documents these risks without changing collection semantics or presenting hypothetical fixes as validated.

The October 2026 pre-qualification collector correction respects explicit mux category groups: a category named multiple or other belongs to inactive when the report metadata says so. Named-group mapping takes precedence over the legacy category-label fallback. Checkpoint cutoff and missing-metadata fallback have regression coverage. This correction does not establish parity with the unavailable training extractor, and any new study must freeze the corrected source.
